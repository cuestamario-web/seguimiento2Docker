Ejercicio 1.
---------------------------------------------------------------------------
1. Dockerfile:

FROM python:3.11-alpine
WORKDIR /app
COPY . .
ENV NOTA_MINIMA=3.0 
CMD ["python", "app.py"]

2. respuestas:

 -¿La aplicación usa alguna variable de entorno? ¿Cómo se llama?
Sí, usa una variable de entorno. Normalmente se llama NOTA_MINIMA (o similar según el código exacto en app.py).

- ¿Es obligatoria? ¿Qué pasa si no se define?
  No es obligatoria, ya que el código tiene un valor por defecto estructurado (generalmente 3.0). Si no se define, simplemente usa ese valor por defecto para evaluar a los estudiantes.

- ¿Qué cambia en el resultado si se modifica su valor?
  Cambia la condición (el umbral) con la cual el programa decide y muestra en consola si un estudiante "aprobó" o "reprobó" la materia.

3. comandos:

- Construir la imagen: docker build -t reporte-notas .
- Ejecución por defecto: docker run reporte-notas
- Ejecución cambiando la variable: docker run -e NOTA_MINIMA=4.0 reporte-notas


---------------------------------------------------------------------------
Ejercicio 2.
---------------------------------------------------------------------------
1. Dockerfile:

FROM node:18-alpine
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm install
COPY . .
ENV SEDE_CAFETERIA="Sede Principal"
EXPOSE 3000
CMD ["node", "src/server.js"]

2. respuestas:

- ¿En qué puerto escucha la aplicación?
  La aplicación escucha en el puerto 3000.

- ¿La aplicación usa alguna variable de entorno? ¿Cómo se llama?
  Sí, usa la variable de entorno llamada SEDE_CAFETERIA.

- ¿Es obligatoria? ¿Qué pasa si no se define?
  No es obligatoria. Si no se define, la aplicación iniciará normalmente y la API devolverá la respuesta con la información por defecto que esté codificada en el archivo (generalmente "Sede Principal" o similar).

3. Comandos:

- Construir la imagen: docker build -t cafe-api .
- Contenedor Sede 1: docker run -d -p 8080:3000 -e SEDE_CAFETERIA="Sede Principal" --name cafe-central cafe-api
- Contenedor Sede 2: docker run -d -p 8081:3000 -e SEDE_CAFETERIA="Sede Norte" --name cafe-norte cafe-api


---------------------------------------------------------------------------
Ejercicio 3.
---------------------------------------------------------------------------
1. Dockerfile

FROM eclipse-temurin:21-jdk-alpine
WORKDIR /app
COPY src/ ./src/
COPY datos/ ./datos/
RUN find src -name "*.java" | xargs javac
ENV ARCHIVO_INVENTARIO="datos/inventario.txt"
CMD ["java", "-cp", "src", "bodega.Main"]

2. respuestas:

- ¿Qué archivos además del código necesita la aplicación dentro del contenedor?
  Necesita la carpeta "datos" y los archivos de texto que contienen la información a procesar, como "inventario.txt" e "inventario_sede_norte.txt".

- ¿La aplicación usa alguna variable de entorno? ¿Cómo se llama?
  Sí, usa una variable de entorno para identificar la ruta del archivo, generalmente llamada ARCHIVO_INVENTARIO.

- ¿Es obligatoria? ¿Para qué sirve?
  Sirve para indicarle al programa exactamente qué archivo de texto debe abrir y leer para hacer los cálculos del inventario. Si no se define, tomará el archivo por defecto (inventario.txt).

3. Comandos:

- Construir la imagen: docker build -t bodega-app .
- Ejecución para la sede norte: docker run -e ARCHIVO_INVENTARIO="datos/inventario_sede_norte.txt" bodega-app
